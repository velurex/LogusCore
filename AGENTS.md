# Project Guidelines & Rules

## Language Policy

1. **English Only for Project Assets**:
   - All documentation (including Markdown files, guides, design specs, and architectural overviews) must be written exclusively in English.
   - All source code, identifiers, function and variable names, classes, interfaces, enums, packages, and namespaces must be in English.
   - All code comments, docstrings, KDoc annotations, and inline explanations must be written exclusively in English.
   - All Git commit messages, pull request descriptions, issue templates, and changelogs must be written in English.

2. **Multilingual Prompts & Instructions**:
   - Regardless of the language used in prompts, tasks, questions, or user instructions, all generated code, comments, documentation, and project files must strictly be produced in English.

3. **Chat Communication**:
   - In direct chat interactions and conversations, always respond in the language in which the user provided their prompt.
   - Any generated project assets, code, comments, and documentation must remain strictly in English.

## Markdown Documentation Guidelines

1. **Relative Links Only**:
   - When creating or editing Markdown documents (`.md`), exclusively relative links must be used to reference repository files, directories, and internal resources.
   - Never use absolute file system paths in Markdown links.
