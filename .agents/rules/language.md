# Language and Documentation Rule

## Strict English Policy

* **Documentation & Specifications:** All technical documentation, readmes, architectural diagrams, implementation roadmaps, and guides must be authored exclusively in English.
* **Code & Comments:** All source code, naming conventions, KDoc/Javadoc comments, inline comments, and test descriptions must strictly be in English.
* **Instruction Language Agnostic:** Regardless of the language in which tasks, queries, or prompts are received, any created or updated project artifacts, source code, comments, and documentation must always be written in English.
* **Chat Communication:** In chat interactions and direct conversation responses, always reply in the language in which the user prompted or asked the question. All project assets and code artifacts produced must still strictly remain in English.
